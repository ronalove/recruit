# Inventaire de dev-interface

Ma part : `board.rs` (2 960 lignes de code, 2 125 de tests), `menu.rs` (720 + 65), `menu/sheet.rs` (2 365 + 880, dont un `fixture` de 100), `menu/draw.rs` (1 185 + 460), `menu/quick.rs` (173 + 365), `mux/chrome.rs` (1 145 + 1 285), `mux/cards.rs` (190 + 150), `look.rs` (553 + 155). Relu sans compiler. Les comptes d'usage viennent d'un script qui compte, par fonction, les occurrences dans le code (hors tests) et dans les tests, puis de lectures ciblées.

Constat d'ensemble : ma zone ne porte presque rien de tmux. Le seul lien est `backend::of(..)` (trait `Backend`) dans le tableau de bord, plus un format de texte hérité de `Backend::client_terminals`. Les gains sont ailleurs : des fichiers trop gros (`board.rs`, `sheet.rs`, `chrome.rs`), une même chose représentée plusieurs fois (la carte d'un membre, ses réglages d'affichage, trois `fit` / `wrap`, deux horloges) et des commentaires d'étapes caducs. Aucun code mort que clippy ne verrait déjà ; les seuls items « tests seulement » sont déjà sous `#[cfg(test)]`.

## Hors refacto

1. `board::fit` et `board::wrap` comptent des `char`, pas des colonnes : un texte de tâche ou un nom de membre à caractères larges (CJK, emoji) déborde de sa carte ; `canvas` le rogne sans qu'on voie le « … ». Petit ; à corriger par Simplifier 6 si l'architecte l'accepte comme correction.
2. Aucun autre bug confirmé dans ma part. Vu et non retenu : `Tail::read` (`board.rs:2429`) repart de zéro si le fichier rétrécit mais pas s'il est remplacé par un plus gros (une conversation recréée avec le même nom : improbable) ; `menu.rs:watch` appelle `claude agents` toutes les 2 s quand le tableau de bord est éteint, comme prévu par la décision du 2026-10-08.
